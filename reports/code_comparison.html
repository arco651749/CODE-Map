❌ 改造前：脆弱的 Ad-hoc 寫法 (原 app.js) 存在幽靈渲染漏洞
// 依賴脆弱的全域字串變數 let activePreviewFile = null; async function openPreview(relPath) { activePreviewFile = relPath; drawer.hidden = false; body.innerHTML = 'Reading content...'; try { // ⚠️ 發起非同步請求 (延遲未知) const data = await fetchApi('/api/file-content', { body: { path: relPath } }); // ⚠️ 僅做路徑比對，防不住抽屜關閉後的殘留非同步 if (activePreviewFile !== relPath) return; // ⚠️ 若 render 內部也是非同步 (如 PDF)，此處會再度失控！ await previewManager.render(body, data, context); } catch (err) { if (activePreviewFile !== relPath) return; body.innerHTML = 'Error'; } } function closePreview() { drawer.hidden = true; body.innerHTML = ''; activePreviewFile = null; // 僅清空路徑，未廢棄在途請求 }
  • 致命缺陷 1：無交易代號 (Transaction ID)。若點擊 A（慢）➔ 點擊 B ➔ 快速再點回 A，A 的舊請求會誤以為自己是當前的 A，造成幽靈資料覆蓋。
  • 致命缺陷 2：關閉不徹底。使用者關閉抽屜後，慢速請求若回傳，容易再度污染 DOM 結構。
✅ 改造後：TLA+ 形式化狀態機 (代數序號 Guard) 數學可證 0 競態
// 封閉狀態機與單調遞增代數序號 class FormallyVerifiedPreviewMachine { state = 'CLOSED'; // 'CLOSED' | 'LOADING' | 'READY' | 'ERROR' activeReqId = 0; // 遞增流水號 (Token Guard) async openPreview(relPath) { const reqId = ++this.activeReqId; // 瞬間作廢先前所有請求 this.state = 'LOADING'; this.renderLoadingUI(relPath); try { const data = await fetchApi('/api/file-content', { body: { path: relPath } }); // 🛡️ 【TLA+ 安全不變量守門員】 if (this.activeReqId !== reqId || this.state === 'CLOSED') { return; // 物理阻斷！過期或已關閉時絕對零副作用 } this.state = 'READY'; this.renderReadyUI(data); } catch (err) { if (this.activeReqId !== reqId || this.state === 'CLOSED') return; this.state = 'ERROR'; } } closePreview() { this.activeReqId++; // 序號再次 +1，作廢當前請求 this.state = 'CLOSED'; this.cleanupUI(); } }
  • 數學保證 1：代數單調性。activeReqId 單調遞增，任何異步 callback 醒來時，只需比對 reqId == activeReqId，後浪必推翻前浪。
  • 數學保證 2：狀態原子性。抽屜一關閉（state = 'CLOSED'），在途的非同步網路封包即使到達也全部被安全過濾。
